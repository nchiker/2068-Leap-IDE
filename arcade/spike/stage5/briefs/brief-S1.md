# Your item: S1, the gallery strip (worktree given in the prompt)

Owner report (2026-11-16): in Starfall's Sprites tab only one sprite is visible; the editor edits one asset at a time and the others are in a drop-down and the project panel.

Build a **gallery strip**: a row of small thumbnails of EVERY asset of the tab's kind at the top of the Sprites, Tiles (tile sets), Maps and Models editors. The edited asset is highlighted, a click selects it (through the host's `selectAsset(kind, name)` / the editor's own `select(name)`, whatever the editor already does for its drop-down; the drop-down stays). The strip updates when assets are added, renamed, deleted or edited (the editor's `refresh()` path). It scrolls horizontally when it is long (no page scroll). Each thumbnail carries the asset's name (title tooltip + a small caption), uses `data-role="gallery-item"` and `data-asset="<name>"`, the strip is `data-role="gallery-strip"`, highlighted item has class `current` (use whatever class naming the editor's CSS uses, but keep these data attributes).

Design:
* ONE pure helper `src/tools/asset-thumbs.js` (no DOM; Node can import it): `thumbSprite(asset, opts)`, `thumbTileset(asset, opts)`, `thumbMap(asset, tilesets/project, opts)`, `thumbModel(asset, opts)` each returning `{w, h, rgba: Uint8ClampedArray}` (or `{w,h,data}` - your choice, documented in the header) scaled to fit a box (default 48 x 48, keeping aspect, nearest neighbour, transparent or panel-neutral background). Reuse what exists, do not re-implement: the sprite editor's / sprite-model's frame pixel rendering and palette, `tile-model.js` `tilePixels` / `fromAsset`, the map editor's cell rendering (look how it draws a map with its tile set; a map whose tile set is missing gets a plain placeholder), `model-preview.js` `previewSegments` for models (a fixed yaw). A tile set thumbnail is a grid of its tiles (16 x 8 at most shown; if more than fit, the first ones). A sprite's thumbnail is its first frame, in its own colours (rows' ink / paper per the editor's rules). A map's thumbnail is the whole map scaled down. Keep every function total: a malformed asset gives a placeholder, never throws.
* Each editor gets a small `renderGallery()` that draws the thumbnails into `<canvas>` elements with `putImageData` (no innerHTML; names through textContent). Draw lazily and cache by asset JSON string so a big project does not redraw all thumbnails on every pixel edit: only the edited asset's thumbnail is re-rendered on an edit (compare `JSON.stringify`).
* CSS: use the editor's own variables, add the rules to the editor's CSS string. The strip must be at most 72 px high and must not break the layout at 1280 px wide.
* Studio facts: the editors are created by `createSpriteEditor`, `createTileEditor`, `createMapEditor`, `createModelEditor` (container, host); host members are optional (see each file's header). Selecting an asset in the strip must work with the host members the editor already uses for its drop-down.

Own files: `src/tools/asset-thumbs.js` (new), `src/tools/sprite-editor.js`, `src/tools/tile-editor.js`, `src/tools/map-editor.js`, `src/tools/model-editor.js`, `tests/asset-thumbs.mjs` (new, Node), and the existing smoke tests of those four editors (`tests/sprite-editor-smoke.mjs`, `tests/tile-editor-smoke.mjs`, `tests/map-editor-smoke.mjs`, `tests/model-editor-smoke.mjs`; find their exact names with ls) to which you add checks: the strip lists every asset of the project, the current one is highlighted, a click on another selects it (the editor shows it), adding / renaming / deleting an asset updates the strip, a pixel of a thumbnail canvas is not blank for a non-blank asset, no page errors.
